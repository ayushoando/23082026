# OandO Workflow Power

Route each request to the smallest repository capability that can answer it. Authority order is current user instruction, live code and fresh command output, `AGENTS.md`, `Agents/`, then durable docs.

## Repository skills

- `oando-master` — first router and completion contract.
- `repo-map` — repository orientation and canonical locations.
- `graph-impact` — import-graph blast radius and suggested checks.
- `fork-boundaries` — Studio/Planner separation.
- `focss-css` — Tailwind v4/FOCSS tokens and zones.
- `db-migrations` — Admin versus Products database routing and migration safety.
- `planner-studio` — implementation planning and task structure.
- `powers-skills-model` — Kiro capability model and containment.
- `verify-and-gate` — explicit-owner-authorized behavioral validation only.

## Local power routing

- Traces, metrics, Prometheus/Grafana, client-error ingestion, and hard blockers → `observability`.
- Consent, analytics events, queues, conversion contracts, and KPIs → `analytics`.
- CSP/headers, sessions, API authorization, CSRF, SVG, origins/uploads, rate limits, and security commands → `security`.
- Repository orientation, graph analysis, fork checks, CSS, migrations, and planning → the matching repository skill; no external power is required.

These powers are routing documents. They bundle no MCP server and do not prove runtime installation.

## Verification ownership

Tests, typechecks, gates, coverage, builds, browser checks/runners, and local-service commands are owner-authorized. The enabled `block-agent-tests` `PreToolUse` hook matches `execute_pwsh|control_pwsh_process` and invokes `.kiro/hooks/block-agent-tests.mjs` before agent shell execution. Do not retry, bypass, weaken, or remove a denial; provide the exact command for the owner to run directly.

Lightweight save hooks retain only Studio/Planner boundary checks and FOCSS/UI checks. They do not establish broad validation success.

## MCP status

Canonical schema snapshots are under `.kiro/mcp/{chrome-devtools,cloudflare-docs,github,tasks}/`. Schema presence is metadata, not a configured or installed server. `.kiro/settings/mcp.json` currently has an empty `mcpServers` object, so no server is workspace-configured. Runtime availability is not verified without a direct registry check.

## Repository constraints

Use root `pnpm`, never create worktrees, preserve unrelated changes, keep UI work on `http://localhost:3000`, respect the production read-only filesystem, and keep Kiro-owned implementation under root `.kiro/`.
