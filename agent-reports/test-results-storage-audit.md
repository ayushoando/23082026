# Test Results & Artifact Storage Architecture Audit

**Date:** 2026-09-04  
**Target:** [`results/`](file:///d:/23082026/results/), [`tests/INVENTORY.md`](file:///d:/23082026/tests/INVENTORY.md), and [`agent-reports/`](file:///d:/23082026/agent-reports/)  
**Relevant Inquiry:** *"Why are test results machine generated not in results?"*

---

## Executive Summary

A key architectural rule defined in [`AGENTS.md`](file:///d:/23082026/AGENTS.md) § 3 (Layout) and § 8 (Traps) states:
> *"results/ holds generated evidence only — no hand-written Markdown reports or audit archives."*  
> *"Production filesystem is read-only. Clean results directory to keep only files $\le$ 4 hours old."*

This audit clarifies why certain machine-generated artifacts (such as [`tests/INVENTORY.md`](file:///d:/23082026/tests/INVENTORY.md)) live in tracked source directories rather than `results/`, and outlines the strict lifecycle rules separating ephemeral execution output from durable repository documentation.

---

## 1. The Dual-Storage Model

The repository separates machine-generated outputs into two distinct lifecycle tiers:

| Tier | Directory | Git Tracking | Retention / Lifecycle | Purpose & Contents |
| :--- | :--- | :--- | :--- | :--- |
| **Tier 1: Ephemeral Evidence** | [`results/`](file:///d:/23082026/results/) | **Gitignored** | $\le$ 4 hours TTL (pruned automatically) | Raw Vitest JSON dumps, Playwright video traces, coverage HTML, test execution logs, and `results/test-inventory.json`. |
| **Tier 2: Durable Inventories** | [`tests/`](file:///d:/23082026/tests/) & [`agent-reports/`](file:///d:/23082026/agent-reports/) | **Committed to Git** | Permanent (Version Controlled) | Human-readable documentation, census inventories ([`tests/INVENTORY.md`](file:///d:/23082026/tests/INVENTORY.md)), and audit reports. |

---

## 2. Why is `tests/INVENTORY.md` NOT in `results/`?

While [`tests/INVENTORY.md`](file:///d:/23082026/tests/INVENTORY.md) is machine-generated by [`scripts/general/generate-test-inventory.mjs`](file:///d:/23082026/scripts/general/generate-test-inventory.mjs), it is intentionally committed inside `tests/` rather than `results/` for three critical reasons:

### Reason 1: CI Governance Ratchet & Diff Tracking
When a pull request adds or deletes a test, the diff in `tests/INVENTORY.md` appears directly in the GitHub PR review. Reviewers can immediately see:
```diff
 | Kind | Count |
-| Vitest executable files | 775 |
+| Vitest executable files | 777 |
```
If this file lived in `results/`, git would ignore it, making automated test-count ratchet verification impossible.

### Reason 2: `pnpm run docs:check` Gate Contract
In CI pipelines, [`scripts/general/generate-docs.mjs:41-58`](file:///d:/23082026/scripts/general/generate-docs.mjs#L41-L58) executes:
```javascript
const diff = spawnSync("git", ["diff", "--exit-code", "--", "tests/INVENTORY.md"]);
if (diff.status !== 0) {
  console.error("Generated artifacts are stale — run `pnpm run docs:sync` and commit");
  process.exit(1);
}
```
This gate ensures that no developer can add a test without updating the tracked test inventory. This check requires Git tracking.

### Reason 3: Dual Output Emission
The generator script actually emits **both**:
- **Durable Version:** `tests/INVENTORY.md` (Markdown format for developers and Git diffs).
- **Ephemeral Version:** `results/test-inventory.json` (JSON format in `results/` for programmatic consumption during test runs).

---

## 3. Results Directory Hygiene Rules

1. **4-Hour TTL:** Files in `results/` older than 4 hours are treated as stale artifacts and pruned.
2. **Zero Manual Documents:** Never hand-write or archive Markdown reports in `results/`. All agent audit findings belong in [`agent-reports/`](file:///d:/23082026/agent-reports/).
