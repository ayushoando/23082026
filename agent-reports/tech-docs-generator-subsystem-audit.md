## Executive Summary

The [`tech-docs-generator/`](file:///d:/23082026/tech-docs-generator/) directory houses an **independent documentation subsystem** that operates as both an offline AST extraction engine and an interactive single-page application (SPA). It inspects the monorepo from the outside, generating structured evidence without polluting production application runtime code (`site/`).

```
tech-docs-generator/ Architecture:
├── scripts/                 # 55 Generator, Extractor & Parity Verification Scripts
│   ├── model.mjs            # Core extraction orchestrator (1,108 lines, 18 domains)
│   ├── generate-all.mjs     # CLI pipeline runner (extract -> validate -> build)
│   ├── extract-*.mjs        # 16 Domain extractors (api, ci, db, deps, routes, etc.)
│   └── filesystem.mjs       # Parity validation and clean staging utilities
├── src/                     # Interactive SPA Viewer (Vite + React)
│   ├── pages/               # 12 Architectural Dashboard Pages (Database, Overview, etc.)

│   ├── index.css            # Standalone Tailwind CSS stylesheet
│   └── App.tsx              # Router shell (HashRouter/BrowserRouter)
├── package.json             # Independent workspace package configuration
├── vercel.json              # Independent Vercel deployment configuration
└── tailwind.config.ts       # Isolated Tailwind theme (does not affect site/focss)
```

## 1. Dual-Engine Operational Mechanics

### Engine A: The Extraction Pipeline (`scripts/`)
Executed via `pnpm run tech-docs:generate` or `node tech-docs-generator/scripts/generate-all.mjs`:
1. **Clean Staging:** `filesystem.mjs` clears `generated-documents/` and verifies disk writeability.
2. **AST Extraction:** 16 domain extractors crawl the monorepo:
   * [`extract-routes.mjs`](file:///d:/23082026/tech-docs-generator/scripts/extract-routes.mjs): Crawls `site/app/` to detect all page, loading, error, and API route contracts.
   * [`extract-database.mjs`](file:///d:/23082026/tech-docs-generator/scripts/extract-database.mjs): Scans Drizzle schemas and Supabase migration tables.
   * [`extract-dependencies.mjs`](file:///d:/23082026/tech-docs-generator/scripts/extract-dependencies.mjs): Parses `pnpm-lock.yaml` and maps licensing and bundle weights.
   * [`extract-repo-graph.mjs`](file:///d:/23082026/tech-docs-generator/scripts/extract-repo-graph.mjs): Emits complete AST import/export relationships into `generated-documents/data/repo-graph.json`.
3. **Parity Validation:** Verifies generated outputs against `PARITY_DATA_FILES` to ensure byte-for-byte fidelity.

### Engine B: The Interactive SPA (`src/`)
* **Framework:** React 19 SPA bundled with Vite.
* **12 Dedicated Pages:**
  1. `Overview.tsx`: System scorecard, core metrics, and active blockers.
  2. `Architecture.tsx`: Topology diagrams, edge proxying, and data flow.
  3. `Database.tsx`: Schema diagrams and migration status *(contains stale data; see below)*.
  4. `ApiDesign.tsx`: Route contracts, auth boundaries, and payload specs.
  5. `TechStack.tsx`: Complete inventory of runtime frameworks and dependencies.
  6. `CodeOrganization.tsx`: Monorepo structure, folder roles, and import policies.
  7. `Features.tsx`: Matrix of live product features across Studio and Planner.
  8. `Security.tsx`: RBAC models, token resolution, and header configurations.
  9. `Performance.tsx`: Bundle analysis, asset caching, and Core Web Vitals.
  10. `Workflows.tsx`: Developer guides and common maintenance playbooks.
  11. `Testing.tsx`: Two-lane test coverage and execution matrices.
  12. `Deployment.tsx`: Vercel edge, Cloudflare worker proxy, and R2 assets.

## 2. Testing & CI Verification (Vitest Lane 2)

Tech-Docs is treated as a **first-class tested artifact**. The repository maintains two distinct Vitest lanes:
* **Lane 1 (`vitest.config.ts`):** Application unit and integration tests (777 files).
* **Lane 2 ([`tests/vitest.tech-docs.config.ts`](file:///d:/23082026/tests/vitest.tech-docs.config.ts)):** Runs dedicated tech-docs parity and contract assertions.

Both lanes must pass in CI (`pnpm run test` executes both in succession).

## 3. Disconnects & Technical Debt

1. **Stale Diagrams in `Database.tsx`:**  
   Hardcodes archived tables (`users`, `leads`, `activity`). Needs to import live schema from `generated-documents/data/database.json`.
2. **Orphan Component Graph:**  
   The 25KB Mermaid graph generated by `generate-page-component-graph.mjs` has no corresponding route in `App.tsx`.
3. **Heavy AST Graph Payload:**  
   `repo-graph.json` (33.9 MB) is too large for client-side browser loading and causes memory pressure.
