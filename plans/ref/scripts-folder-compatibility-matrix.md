# Scripts-folder compatibility matrix

## Purpose and evidence boundary

**Purpose.** Freeze the completed audit's proven compatibility surface before any later cleanup implementation. This is a planning-only matrix: it records preservation, caller, wrapper, rollback, and owner-decision dependencies; it does not change script behavior or select a canonical implementation.

**Evidence sources (exclusive).** [`plans/ref/scripts-folder-audit.md`](./scripts-folder-audit.md) (the completed audit) and [`plans/scripts-folder-audit/tasks.md`](../scripts-folder-audit/tasks.md) (Task 1 plan). No runtime, source, package, workflow, or script files were inspected for this matrix.

**Read-only/no-action boundary.** This document authorizes no script, package, workflow, source, configuration, archive, or documentation change outside this planning file. It does not establish runtime safety, select an owner, approve a move, or approve an archive. All tests, gates, builds, browser suites, database/deployment/storage operations, and persistent mutations remain deferred to explicit user invocation.

**Completed audit baseline.** 247 visible scripts/support artifacts: **106 `keep`**, **141 `maybe`**, **0 archive candidates**. The `keep` set is protected by evidenced caller, documented gate/path policy, or shared-helper evidence; every `maybe` remains active and untouched because caller, lifecycle, ownership, import, or safety evidence is incomplete. See audit **Task 3.4**, `DSP-KEEP-001`, `DSP-MAYBE-001`, and **Task 4.3**.

## Preservation rules

1. **No deletion.** No artifact is deleted by this program or this task.
2. **`maybe` stays active.** The 141 `maybe` artifacts stay active and untouched at their current paths. Their incomplete safety/caller evidence is a block, never permission to move, consolidate, archive, disable, or edit them.
3. **Protected paths and callers remain valid.** Proven caller paths/commands, the 26 documented `scripts/general/` gate-critical artifacts, the 13 path-stable SVG artifacts, and the eight shared helpers are preserved. `tech-docs-generator/scripts/fake-test-audit.mjs` is a documented external exception, not a missing or mislocated `scripts/general/` artifact.
4. **Compatibility wrapper before relocation.** A future approved relocation/consolidation must first retain the old path/command as a compatibility wrapper, then migrate recorded caller classes in an ordered reversible sequence. The wrapper remains until owner-approved evidence review confirms recorded callers have migrated and rollback remains possible.
5. **Validation is user-owned.** Any later static comparison, test, gate, build, browser suite, database/deployment/storage action, or runtime validation requires explicit user invocation. Dispatcher-level static controls do not prove terminal-script safety.
6. **Archive is not current work.** `scripts/archive/` is a future target family only. There are zero candidates now; no location is selected, and `.archive/audit/` remains excluded.

## Mandatory migration gate for a later implementation change

A later implementation may proceed only when every applicable item below is recorded and approved for the specific artifact/capability:

- [ ] **Full caller listing:** identify every affected package command, `run-ops` key/root alias, registry consumer, workflow, documentation caller, import, and direct invocation within the completed scope; state excluded/dynamic/external limits.
- [ ] **Owner:** record an explicit accountable owner and the affected caller-owner decisions. No owner may be inferred from a path, name, or policy location.
- [ ] **Safety contract where applicable:** before changing an operational artifact, record target/database classification, environment and secret-boundary names only, preview/apply behavior, target guard, confirmation/approval, backup/recovery, failure behavior, and rollback. Incomplete safety evidence blocks the change.
- [ ] **Wrapper approach:** add/retain the old command, path, alias, re-export, or compatibility wrapper before relocating or consolidating the implementation.
- [ ] **Command and documentation migration:** update one recorded caller class at a time only after compatibility is available; preserve aggregate/alias semantics unless an owner-approved replacement plan explicitly records them.
- [ ] **Rollback:** record the reversible restoration sequence, retained legacy command/path/wrapper, caller restoration order, and any prerequisite evidence. For archive proposals, include the separate manifest/index/hash/restoration requirements.
- [ ] **Explicit user-invoked validation:** after a separately approved implementation change, perform only the owner-selected static/manual comparison and any tests, gates, builds, browser, database, deployment, storage, or runtime validation explicitly invoked by the user. This matrix does not invoke validation.
