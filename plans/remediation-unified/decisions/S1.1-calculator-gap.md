# Decision: S1.1 — Calculator owner gap resolution

**Date:** 2026-08-27  
**Task:** S1.1 — Resolve the calculator owner gap  
**Files:** 
- `site/app/(site)/tools/office-space-calculator/page.tsx`
- `site/app/(site)/tools/meeting-room-capacity-calculator/page.tsx`
- `site/focss/site/components/shared/tools.css` (new)

## Problem

Two live marketing pages render unstyled content blocks:

1. **Office Space Calculator** (`/tools/office-space-calculator`)
2. **Meeting Room Capacity Calculator** (`/tools/meeting-room-capacity-calculator`)

Both pages render:
- `div.tools-engine-placeholder` — calculator interface placeholder
- `div.tools-faq` — FAQ section

Neither class has any corresponding CSS rules in `site/focss/**/*.css`, resulting in completely unstyled content blocks on live pages.

## Decision

**Style the placeholder in a site sheet** rather than withdrawing the routes or building the real calculator.

## Rationale

### Options considered

1. **Build the real calculator (product decision)** — Out of scope per remediation plan
2. **Withdraw the routes** — Already `indexable: false`, but pages exist and should render styled content
3. **Style the placeholder** — Provides immediate visual improvement, maintains page existence

### Chosen approach benefits

1. **Immediate fix:** Resolves the visual defect without waiting for product decisions
2. **User experience:** Provides basic styling for content that users can actually see
3. **Maintainability:** Clear CSS ownership in shared components
4. **Reusability:** Pattern can be extended to other tool placeholder pages
5. **Minimal risk:** Doesn't affect application logic or remove existing routes

## Implementation

### CSS location choice

**New file:** `site/focss/site/components/shared/tools.css`

**Reason:** No existing canonical owner fits because:
- These are tool-specific pages (`/tools/*`)
- Not homepage components (separate from `homepage/`)
- Not product pages (separate from `products/`)
- Shared styling pattern applies to both calculator pages
- Future tool placeholder pages can reuse the same styles

### CSS design principles

1. **Consistency:** Uses existing design tokens (`--space-*`, `--radius-*`, `--color-*`)
2. **Accessibility:** Proper contrast, semantic HTML support
3. **Responsive:** Mobile-first approach with tablet/desktop enhancements
4. **Temporary mindset:** Clearly documented as placeholder styling

### Key styling decisions

1. **Placeholder visual:** Neutral background with subtle border, loading indicator (⏳)
2. **FAQ structure:** Clear visual separation, question/answer hierarchy
3. **Spacing:** Appropriate vertical rhythm matching site standards
4. **Typography:** Consistent with marketing page type scale
