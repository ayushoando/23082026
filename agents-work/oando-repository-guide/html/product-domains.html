Planner and Studio fork boundary

They are separate applications. They may meet through approved backing data/API contracts but never import each other. They have separate canvas scales, state, UI, and persistence assumptions.
Decide whether [capability] belongs in site/platform/shared/. Do not cross-import
Planner and Studio or duplicate code before comparing both forks.

UI and product support

Styling

Tailwind v4 plus FOCSS zones: site, admin, Planner, Studio. Use semantic tokens and do not cross zones.

Catalog/assets

Start in site/lib/catalog/, plan symbol contract, and catalog asset storage helper.

AI/search

Start in site/lib/ai/mastra/; retrieval uses Bedrock, LanceDB, Orama, and Fuse.
