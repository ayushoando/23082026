Release sequence

Migrations→Required seed→Code deployment→Appropriate verification

Before any external action, identify environment, DB ownership, backup/recovery, rollback, exact command, and expected effect.

Backup, recovery, and maintenance

  • Nightly backup automation: .github/workflows/supabase-backup-r2.yml.
  • R2 supports database dumps, catalog snapshots, and repository backups.
  • Bad deploy, migration rollback, provider recovery/PITR, catalog degraded mode, and Planner drafts have different recovery paths.
  • SITE_MAINTENANCE_MODE=readonly is an API write gate; it does not change production filesystem behavior.

Safe prompts

Create a read-only release plan for [change]. State target, migrations, seed, code
order, risk, backup/rollback, and exact approval points. Do not deploy.
Create a read-only incident plan for [symptom]. Identify provider/surface, safe
observations, customer impact, fallback, recovery path, and approval points.
